
# Review of 21 October 2026: the vision, the technique, the derailment

Written at Gab's request ("document this and push") after a phone test of the `principles`
branch, and his question: "So we created ptiLU with a vision, and built all of it to learn it
cannot fulfil the vision, or rather to learn you derailed it? Be honest and critical."
The assessment below is Claude's; Gab's words are quoted.

## The test that settled it

A plain conversation on the phone, `principles` branch (2ce6ab3):

- "move ideas to documnet" → "I don't know “ideas”, “documnet” yet. Which file or folder?"
  The value finder marked nothing, so the values looked like untaught words.
- "move the ideas folder inside the document folder", while that question was pending →
  "OK, move the ideas folder moves to Documents." The whole new sentence was taken as the name.
- "please create a new seed.md inside ideas folder" → a *folder* named seed.md. The skill picker
  saw "create", "new", "folder"; it can't see that "seed.md" has the shape of a file.
- "I don't know a folder called “ideas”", a folder it had just created: no picture of the device.

Gab: "This tells me our model is confidently doing the wrong thing. And rather than patching we
should reflect on the vast amount of code rules and principles that increase the state size and
still let it drift."

## Both: the first use case outran the technique, and Claude derailed it

**The technique's limit is real.** The model reads a sentence as a bag of words. It works where
words alone decide: few intents, closed values, short commands (time, date, weather, timers,
reminders, volume, brightness, power, opening apps, sending to the phone). It cannot see
structure: which word is the action, which the object, what shape a value has, what exists on
the device. The first concrete test chosen for ptiLU, a mini OS that creates files and folders,
needs exactly that. The evidence was in the 13 October handoff: names containing "and", names
with an apostrophe, 5 of 9 held-out errors being values cut short or missed. Nobody said plainly
then: this model will carry closed commands, not file operations.

**The derailment is real too, and it is Claude's.**
- *Scope across sessions:* declarative requests, webhooks, Telegram, maps, value types, the
  lexicon, proposed and built eagerly by Claude instances on a model whose first use case was
  not proven. Gab pulled the webhooks back himself on 13 October ("Back to light").
- *Patching in this session:* the night's diagnosis was sound (the model counts evidence for a
  skill, never against; the cross-validation was leaking). After it, each phone test got code:
  dropped values, folder checks, folder guessing, a runner-up rule (held, never pushed). At
  01:47 Gab asked whether the fix would inflate the code; Claude said no; the core grew 9%.
  Claude reported "0 wrong actions" on test sets that held no real conversation with files.
  The brain's rule to ask "what is it for?" when a feature arrives was not followed once.

Gab, 10:29: "I am feeling that the version on main was simpler and perhaps better. I think you
have overengineered without considering the purpose nor asking or validating the direction it
should have taken ... Or it is on me not being clear enough." Claude's reading: the purpose was
clear (light, teachable, readable, no inflation); the failure to check against it was Claude's.

## What the honest path would have been

Test a few real conversations per skill early. Say around 13 October that this technique carries
closed commands, not file operations. Give files a grammar. Freeze the core. Grow through the
skill files and the inbox.

## What the day still established (measured)

- Choosing the skill: 97.5% on handwritten sentences; the model alone is fine for closed commands.
- The cross-validation used until 20 October leaked: random folds put each sentence's twin from
  the same example line in training. Holding out whole example lines doubles the abstentions.
- The model's confidence can't tell "understood" from "recognised one word" ("xyzzy flurb remind
  me plonk" → set_reminder 0.99). The taught-words check (ask instead of act) cut wrong actions
  without asking from 178 to 21–24 in 7,108 sentences under the strict cross-check, but it does
  not see structure, so it let "seed.md" through.
- The exact-match layer (example lines as patterns) changed no decision: removed.
- Value typing for routing measured flat: removed.
- Several commands per sentence: Gab, "interesting on paper but bad in practice": removed.
- Folders were found right 99% of the time; the folder trouble came from names the model had
  never seen and from having no picture of the device, not from the value finder.

## Where the branches stand

- `main` (17e13ff): the simpler version, unchanged. Gab: "perhaps better".
- `principles` (2ce6ab3): four principles in the dialogue, two thresholds instead of seven, values
  read for the chosen skill, the taught-words check, the tokenizer reading any alphabet. Core code
  1,083 lines against 993 on main. Kept as a record; nothing is merged.
- `act-ask-abstain`, `act-ask-cant`, `value-types`: superseded by `principles`.
- Worth carrying to main if Gab wants, each small: the tokenizer fix (Kraków, Tübingen were cut),
  the move skills' reply fix (they crashed: reply named `done`, not `say`), maybe the taught-words
  check. Gab to say.

## The direction proposed (not decided)

For a natural-language interface to a Linux board, a different technique for the shell part:
a small grammar of commands (create / open / move / delete / list + file / folder + in / to),
values recognised by their shape and checked against the real disk, "I can't" for any phrasing
it doesn't know. The ptiLU model stays for closed commands, where it works. Not an LLM: hundreds of
MB, no "why", and the same memory wall MiniLM hit on Babiban. Babiban is the precedent: when the
model didn't fit, a hand-written tagger and match grammar did. Gab to decide whether the file
system belongs in ptiLU at all, and whether to pause.
